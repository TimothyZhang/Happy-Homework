# 开发状态说明

本文档用于快速说明 `miniapp-starter` 当前到底已经做到了哪一步，哪些是原型，哪些是真实链路，哪些仍然待完成。

## 当前项目阶段

当前项目处于：

> **可交互原型 + OCR 接入骨架已完成，但尚未完成真实 OCR 联调的 MVP 阶段**

它不是从零开始，也不是可直接上线的正式版本。

---

## 一、已经完成的内容

## 1. 小程序整体骨架
项目已经具备完整的小程序基础结构，包括：
- 全局配置 `app.js / app.json / app.wxss`
- 多页面结构
- TabBar 导航
- 基础视觉风格

## 2. 核心产品主链路原型
已实现以下主链路的前端交互原型：
- 首页总览
- 作业列表
- 作业新增 / 编辑 / 删除
- 排期页
- 宠物页
- 统计页
- 个人页

## 3. 作业管理基础逻辑
已支持：
- 新增作业
- 编辑作业
- 删除作业
- 标记进行中 / 已完成
- 展示计划时间与预计时长

## 4. 奖励与宠物反馈
已支持：
- 完成作业后获得金币
- 全部完成额外奖励
- 购买宠物道具
- 宠物成长值、开心值、饱腹值变化
- 升级反馈

## 5. OCR 导入链路骨架
已完成以下 OCR 相关能力：
- `pages/ocr-import`：拍照 / 相册导入 / 演示数据
- `pages/ocr-result`：识别结果确认、删除、新增、导入
- `cloudfunctions/homeworkOCR`：云函数入口骨架
- 小程序端已接：
  - `wx.cloud.init`
  - `wx.cloud.uploadFile`
  - `wx.cloud.callFunction`

这说明当前不是“纯页面假流程”，而是已经把真实上传和云函数调用链接上了。

---

## 二、当前仍未完成的内容

## 1. 真实 OCR 服务未接入
目前云函数返回的仍是 mock 文本，还没有接入正式 OCR 服务。

## 2. 云函数部署未形成最终闭环
虽然函数代码已经写好，但还需要：
- 绑定云开发环境
- 在微信开发者工具里部署云函数
- 做真实联调验证

## 3. 数据仍以本地状态为主
当前 `utils/store.js` 仍主要承担本地原型状态管理。

这意味着：
- 当前更偏产品原型 / 演示版本
- 还没有完全迁移到云数据库驱动

## 4. 线上级异常处理仍不足
例如：
- OCR 失败后的精细化错误提示
- 更细的重试机制
- 图片上传失败分类处理
- 导入后的任务去重与清洗

---

## 三、项目中的“真”与“假”边界

为了避免后续沟通混淆，这里明确说明：

### 真实存在的部分
- 小程序多页面代码
- 作业管理交互
- 奖励/宠物交互
- 小程序云开发初始化
- 图片上传到云存储
- 调用云函数入口

### 仍然是 mock / 原型的部分
- 云函数返回的 OCR 文本
- OCR 精准识别结果
- 云数据库正式持久化
- 完整线上化容错能力

---

## 四、适合当前阶段做什么

当前版本最适合用于：
- 产品方案讨论
- 页面流程演示
- 家长使用体验验证
- OCR 交互路径验证
- 技术方案选型确认

当前还不适合直接视为：
- 已完成上线版本
- 已完成真实 OCR 产品
- 已完成正式云开发版

---

## 五、建议下一步

### 第一优先级
- 在 `cloudfunctions/homeworkOCR/index.js` 中接真实 OCR 服务
- 完成云环境绑定与部署
- 跑通真实“拍照 -> 识别 -> 拆分 -> 导入”闭环

### 第二优先级
- 把 `utils/store.js` 中的核心数据迁移到云开发数据库
- 明确 `homeworkTasks / ocrJobs / ocrDraftItems` 数据表结构

### 第三优先级
- 优化 OCR 识别结果页交互
- 优化错误提示与失败重试
- 增加更多真实样本测试

---

## 六、一句话结论

`miniapp-starter` 当前已经是一个方向清晰、页面完整、主链路可演示、OCR 调用骨架已接好的微信小程序项目；下一步的关键，是把真实 OCR 和云开发闭环补上，让它从“强原型”进入“可验证 MVP”。
