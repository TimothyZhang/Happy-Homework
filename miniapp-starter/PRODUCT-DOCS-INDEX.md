# 产品文档索引

这个文件用于快速说明 `miniapp-starter` 项目里每份产品/方案文档各自负责什么。

## 文档列表

### 1. `V1-PRD-homework-pet.md`
**定位：** 小程序整体 V1 产品设计文档。

**覆盖内容：**
- 产品定位与目标用户
- 作业管理主链路
- 时间预估与排期
- 打卡奖励
- 电子宠物养成
- V2 社交能力预留

**适合什么时候看：**
- 想快速理解这个小程序整体想做什么
- 想看 V1 的核心功能边界
- 想看页面结构和产品范围

### 2. `V1-PRD-homework-register-ocr.md`
**定位：** 作业登记本 OCR 专项产品设计文档。

**覆盖内容：**
- 为什么要做整页作业识别
- 用户上传图片后的完整流程
- OCR 识别结果如何拆分成多条作业草稿
- 用户如何编辑确认并导入
- MVP 范围、异常处理与验收标准

**适合什么时候看：**
- 想推进 OCR 导入功能
- 想对齐产品和技术对“整页识别”的理解
- 想明确 V1 该做什么、不该做什么

### 3. `CLOUD-DATA-NOTES.md`
**定位：** 云开发数据结构草案（**未实现**，作为未来多表化的参考）。

**覆盖内容：**
- 规范化多表方案：`users / families / children / homeworkTasks / coinLogs / pets / shopOrders`

**注意：** v1 实际走的是 `user_state` 单文档方案（详见 `CLOUD-SETUP.md`），这份草案是为将来真要拆表时留的参考。

**适合什么时候看：**
- 要讨论多孩子 / 多家庭体系时
- 要把日志型数据拆出来做长期分析时

### 4. `CLOUD-SETUP.md`
**定位：** 微信云开发接入说明。

**覆盖内容：**
- OCR 链路（腾讯云子用户 + AKSK + provider 优先级 + 端到端复现步骤）
- **跨设备数据同步**（`user_state` 集合配置 + 运行时行为 + 数据范围 + 已知限制）
- 当前已接好的调用链 + 还差哪些动作

**适合什么时候看：**
- 第一次跑这个项目（要建 `user_state` 集合）
- 要继续推进 OCR 联调时
- 要查同步机制的具体行为时

### 5. `DEV-STATUS.md`
**定位：** 当前开发状态说明。

**覆盖内容：**
- 项目现在到底做到哪一步
- 哪些功能是真实链路
- 哪些部分仍然是 mock / 原型
- 下一步最关键的研发动作

**适合什么时候看：**
- 需要快速汇报项目进展时
- 需要向别人解释“这个版本到底完成了多少”时

### 6. `TECH-OVERVIEW.md`
**定位：** 项目技术结构说明。

**覆盖内容：**
- 项目结构（含子包 / 自定义 tabBar / cloud-sync）
- 页面结构
- 状态管理（进程内缓存 + 本地 storage + 云数据库三层）
- OCR 技术链路
- 云数据库当前在用的集合 + 设计草案的取舍
- 当前技术风险与下一步建议

**适合什么时候看：**
- 交接项目时
- 准备继续开发代码时
- 上传到 GitHub 后给其他人快速理解项目时

### 7. `V1-VALUES-DESIGN.md`
**定位：** V1 金币 / 衰减 / 商店 / 升级的数值设计备忘。

**覆盖内容：**
- 用户行为假设（每天作业量、完成率、玩耍节奏）
- 金币奖励规则（单项 / 当日全完成 / 7 天连续 / 分享被保存）
- 宠物属性衰减速率（饱腹 / 清洁 / 开心 / 健康）
- 商店道具的价格 / 效果 / 周期
- 升级曲线

**适合什么时候看：**
- 任何调整数值（奖励、衰减、价格、升级阈值）前，必须先回到这里把账重算
- 评估"是不是过于慷慨/吝啬"时

### 8. `V1-PET-ANIMATION-SPEC.md`
**定位：** 宠物动画的视觉与状态机方案。

**覆盖内容：**
- 设计原则（CSS keyframes + class 切换驱动；SVG 拆部位）
- 视角切换规则（idle/sleeping 正面，walking/flying 侧面，eating 斜 3/4，celebrating 正面 + 3D 旋转）
- 各动作的实现细节、跨页触发载体（`globalData.petAnimQueue`）
- 如何给新宠物加动画

**适合什么时候看：**
- 给新增宠物加动画时
- 调整动画时长 / 节奏时
- 排查"宠物动画卡了/不切换"时

3. `V1-PRD-homework-register-ocr.md`
4. `CLOUD-SETUP.md`（**注意：第一次跑前要按末尾章节建 `user_state` 集合**）

## 当前结论

当前这套文档已经能覆盖：
- 项目整体目标
- OCR 专项设计
- 跨设备同步的接入与运行机制
- 云开发接入说明（OCR + `user_state` 同步）
- 在用 vs. 草案的数据结构差异
- 作业本分享端到端流程（发送方编 share path → 接收方落地 `notebook-share` → 保存为新本；详见 `TECH-OVERVIEW.md` 页面结构 + `DEV-STATUS.md` 第 9 项）

- 页面交互稿 / 页面说明
